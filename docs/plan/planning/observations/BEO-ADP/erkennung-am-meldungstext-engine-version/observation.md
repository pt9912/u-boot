# Eine Erkennung am Meldungstext der Engine trägt nur für die gemessene Version

**Sub-Area:** `internal/adapter/driven` (Kürzel ADP, Greenfield laut [`harness/conventions.md`](../../../../../../harness/conventions.md#mr-006)) — der Adapter erkennt einen Fehler des `docker`-Clients vor Beginn einer Sitzung an Strom und Text der Meldung, weil der Exit-Status ihn nicht von dem der Shell trennt; Text und Strom stammen aus Engine und Client, nicht aus u-boot.

Der Adapter unterscheidet einen Fehler des Clients vom Ende der Shell an der Meldung (`Error response from daemon: …` auf der Fehlerausgabe, `OCI runtime exec failed: …` auf der Standardausgabe), gemessen an einer Engine- und Client-Version. Eine andere Engine-Version meldet denselben Fall mit anderem Strom, anderem Status und anderem Text; der Adapter hält die Meldung dann für die Ausgabe der Shell, und `Shell` liefert keinen Fehler. Lokal, wo Engine und Client dieselbe Version tragen, bleibt der Unterschied unsichtbar; die Engine des CI-Runners gehört dem Runner-Image und ändert sich ohne Zutun des Repos. Kein Gate prüft lokal gegen eine zweite Engine-Version.

**Trigger:** ein zweiter Vorgang, in dem eine Erkennung oder ein Test am Text einer Meldung von Engine oder Client auf einer anderen Version abweicht, oder die Entscheidung des Projektinhabers, die Engine-Version der Tests festzulegen oder mit einer zweiten Version zu fahren.
